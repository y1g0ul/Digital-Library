Механизм [[GitLab]] сохранения файлов между [[cicd/GitLab/Job|Job]]s и [[cicd/GitLab/pipeline|pipeline]]s для ускорения их выполнения.

Чаще всего используется для:
- скачанных Python-пакетов;
- npm-зависимостей;
- результатов промежуточной компиляции;
- других файлов, которые дорого создавать или скачивать повторно.

Пример:
```
Первый pipeline
    ↓
pip скачивает зависимости
    ↓
Runner сохраняет cache

Следующий pipeline
    ↓
Runner восстанавливает cache
    ↓
pip использует скачанные файлы
```

### Создание Cache

Кэш описывается через `cache`:
```
test:
  cache:
    paths:
      - .cache/pip/

  script:
    - pip install -r requirements.txt
    - pytest
```

`paths` определяет, какие файлы и директории сохранять.

**Важно:** GitLab кэширует только файлы внутри рабочей директории проекта. Поэтому для Python нужно дополнительно настроить расположение кэша pip.

### Практический пример с Python

```
test:
  image: python:3.13

  variables:
    PIP_CACHE_DIR: "$CI_PROJECT_DIR/.cache/pip"

  cache:
    key: python-dependencies
    paths:
      - .cache/pip/

  script:
    - pip install -r requirements.txt
    - pytest
```

Здесь:
1. `PIP_CACHE_DIR` задаёт директорию для кэша pip.
2. `cache:paths` указывает Runner, какую директорию сохранять.
3. При следующем запуске Runner пытается восстановить кэш.
4. pip использует ранее скачанные пакеты, если они подходят.

При этом `pip install` всё равно выполняется - просто часть работы может быть пропущена благодаря кэшу.

### Cache Key

`key` - идентификатор кэша.

```
cache:
  key: python-dependencies
  paths:
    - .cache/pip/
```

Jobs с одинаковым ключом могут использовать один и тот же кэш, в том числе между разными pipelines одного проекта.

Можно использовать встроенные переменные:
```
cache:
  key: $CI_COMMIT_REF_SLUG
  paths:
    - .cache/pip/
```

Теперь у разных веток могут быть отдельные кэши.

### Автоматическое обновление Cache Key

GitLab позволяет привязать ключ к содержимому файла:
```
cache:
  key:
    files:
      - requirements.txt

  paths:
    - .cache/pip/
```

Если содержимое `requirements.txt` изменится, GitLab сформирует новый ключ кэша.

Это полезно, когда зависимости проекта изменяются.

### Cache Policy

`policy` определяет, как job взаимодействует с кэшем.

|Значение|Поведение|
|---|---|
|`pull`|Только скачать кэш|
|`push`|Только сохранить кэш|
|`pull-push`|Скачать и затем сохранить|

По умолчанию используется `pull-push`.

Пример:
```
test:
  cache:
    key: python-dependencies
    paths:
      - .cache/pip/
    policy: pull

  script:
    - pip install -r requirements.txt
    - pytest
```

Job использует существующий кэш, но не загружает обновлённую версию после завершения.

### Cache и Artifacts

| Cache                                | [[cicd/GitLab/Artifact\|Artifact]]                           |
| ------------------------------------ | ------------------------------------------------------------ |
| Ускоряет выполнение jobs             | Сохраняет результаты jobs                                    |
| Может использоваться между pipelines | Обычно используется для передачи результатов внутри pipeline |
| Не гарантирует наличие файлов        | Предназначен для сохранения конкретного результата           |
| Например, pip cache                  | Например, собранное приложение                               |

**Кэш нельзя использовать как гарантированный способ передачи файлов между jobs.**

Он может отсутствовать, быть удалён или оказаться недоступным другому Runner. Если выполнение следующей job зависит от конкретного файла предыдущей - используй [[cicd/GitLab/Artifact]].

Общая схема:
```
Cache
    ↓
Повторное использование файлов
    ↓
Ускорение pipeline

Artifacts
    ↓
Сохранение результата job
    ↓
Передача следующей job
```
