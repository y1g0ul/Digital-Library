**Artifact** - файл или набор файлов, созданных во время выполнения job и сохранённых GitLab.

Артефакты используются для:
- передачи результатов между jobs;
- хранения собранного приложения;
- сохранения логов и отчётов тестирования;
- скачивания результатов pipeline.

Например:
```
build job
   ↓
Собрала приложение
   ↓
GitLab сохранил artifact
   ↓
deploy job
   ↓
Получила готовое приложение
```

### Создание Artifact

Артефакты описываются через `artifacts`:
```
build:
  stage: build

  script:
    - mkdir dist
    - echo "Hello" > dist/app.txt

  artifacts:
    paths:
      - dist/
```

После выполнения `build` GitLab Runner загрузит директорию `dist/` в GitLab как artifact.

Пути в `artifacts:paths` указываются относительно рабочей директории проекта.

### Передача между jobs

В GitLab jobs из последующих stages по умолчанию автоматически скачивают артефакты jobs из предыдущих stages.

Например:
```
stages:
  - build
  - deploy

build:
  stage: build

  script:
    - mkdir dist
    - echo "Hello" > dist/app.txt

  artifacts:
    paths:
      - dist/

deploy:
  stage: deploy

  script:
    - cat dist/app.txt
```

Процесс:
```
Pipeline
│
├── build
│   ├── Создаёт dist/app.txt
│   └── Загружает artifact в GitLab
│
└── deploy
    ├── Скачивает artifact
    └── Читает dist/app.txt
```

**Важное отличие от GitHub Actions:** в GitLab для обычной передачи артефактов между stages не нужно явно писать команду скачивания.

GitLab Runner делает это автоматически перед выполнением `script`.

### Управление скачиванием - `dependencies`

По умолчанию job скачивает все доступные артефакты предыдущих stages.

Если нужны файлы только от определённой job:
```
deploy:
  stage: deploy

  dependencies:
    - build

  script:
    - ./deploy.sh
```

Теперь `deploy` скачает артефакты только от `build`.

Если артефакты вообще не нужны:
```
dependencies: []
```

### Время хранения - `expire_in`

Артефакты можно автоматически удалять через определённое время:
```
artifacts:
  paths:
    - dist/

  expire_in: 7 days
```

GitLab будет хранить артефакты в течение семи дней, после чего они смогут быть удалены.

При этом GitLab по умолчанию сохраняет артефакты последнего успешного pipeline для каждой ветки или тега, даже если задан `expire_in`. Это поведение можно изменить в настройках проекта.

### Условия сохранения - `when`

По умолчанию артефакты загружаются только при успешном выполнении job.

Можно изменить поведение:
```
artifacts:
  when: always

  paths:
    - logs/
```

Возможные значения:

|Значение|Поведение|
|---|---|
|`on_success`|Сохранить при успешном выполнении|
|`on_failure`|Сохранить при ошибке|
|`always`|Сохранить независимо от результата|

Например, если тесты завершились ошибкой, можно сохранить их логи:
```
test:
  script:
    - pytest > test.log 2>&1

  artifacts:
    when: on_failure

    paths:
      - test.log
```

### Artifact и Cache

Не путать с кэшем:

| Artifact                         | [[cicd/GitLab/Cache\|Cache]]                     |
| -------------------------------- | ------------------------------------------------ |
| Сохраняет результат job          | Ускоряет выполнение jobs                         |
| Используется для передачи файлов | Используется для повторного использования файлов |
| Например, собранное приложение   | Например, скачанные зависимости                  |
| Привязан к конкретной job        | Может переиспользоваться между pipelines         |

Условно:
```
Artifact = результат работы

Cache = экономия времени
```
