Это системные потоки ядра [[Linux]], которые выполняют **отложенную работу ядра** через механизм `workqueue`.

Главная идея: не всю работу ядру нужно выполнять сразу. Если задача не требует мгновенного выполнения, её можно поставить в очередь и обработать позже.

```text
Событие
  ↓
Ядро / драйвер
  ↓
Нужно выполнить сейчас?
  ↓
┌─────────────────────┬─────────────────────┐
│ Да                  │ Нет                 │
│                     │                     │
│ Выполнить сразу     │ work item           │
│                     │      ↓              │
│                     │ workqueue           │
│                     │      ↓              │
│                     │ kworker             │
└─────────────────────┴─────────────────────┘
```

## Workqueue

`workqueue` - механизм ядра для постановки работы в очередь.

В очередь помещается не отдельный процесс, а по сути указание:
> Нужно позже выполнить определённую функцию ядра.

После этого один из потоков `kworker` забирает эту работу и выполняет её.

```text
Подсистема ядра / драйвер
          ↓
       work item
          ↓
       workqueue
          ↓
        kworker
          ↓
     выполнение работы
```

## Зачем это нужно

Некоторые части ядра должны работать очень быстро.

Например, устройство генерирует аппаратное прерывание [[IRQ]]:
```text
Сетевая карта получила данные
        ↓
IRQ
        ↓
Ядро выполняет срочную часть
        ↓
Остальную работу можно отложить
        ↓
workqueue
        ↓
kworker
```

Обработчик прерывания не должен долго занимать процессор, поэтому тяжёлая или менее срочная работа часто переносится на потом.

## Что такое kworker

`kworker` - это **kernel thread**, то есть [[thread|поток]], работающий внутри [[kernel|ядра]].

Посмотреть их можно, например:
```bash
ps aux | grep kworker
```

Пример:
```text
[kworker/0:1-events]
[kworker/1:2]
[kworker/u16:3-events_unbound]
```

Квадратные скобки обычно означают, что это поток ядра, а не обычный пользовательский процесс.

## Имена kworker

Например:
```text
kworker/0:1
```

`0` - CPU, с которым связан worker.

```text
kworker/3:2
```

worker, работающий с CPU 3.

Также встречается:

```text
kworker/u16:2
```

`u` означает **unbound workqueue** - такая работа не привязана строго к одному CPU и может выполняться на подходящем процессоре.

Часть вроде:
```text
-events
-events_unbound
```

может указывать на очередь работы, которую обслуживает поток.

## kworker и CPU

`kworker` не имеет отдельного выделенного процессора или какого-то специального резерва ресурсов.

Это обычный поток ядра, который планировщик [[Linux]] запускает на CPU вместе с остальными потоками.

Поэтому модель:
```text
Есть отдельный свободный CPU для kworker
```
неправильная.

Правильнее:
```text
CPU
├── пользовательские процессы
├── kernel threads
├── kworker
├── ksoftirqd
└── другие потоки
```

Планировщик решает, кому дать процессорное время.

## Если kworker грузит CPU

Если в [[top]] или [[htop]] видно:
```text
kworker/...   80%
```

обычно проблема не в самом `kworker`.

Это означает, что какая-то подсистема ядра постоянно создаёт для него работу.
- драйвер Wi-Fi;
- USB-устройство;
- Bluetooth;
- NVMe/SATA;
- видеодрайвер;
- ACPI;
- энергосбережение;
- устройство, постоянно создающее прерывания.

То есть:
```text
Драйвер / подсистема
        ↓
создаёт много work items
        ↓
workqueue
        ↓
kworker постоянно работает
        ↓
высокая загрузка CPU
```

Поэтому высокая загрузка `kworker` - скорее **симптом**, а не причина проблемы.

## kworker и ksoftirqd

Не стоит путать:
```text
kworker
```

и:
```text
ksoftirqd
```

Оба связаны с выполнением работы ядра, но используют разные механизмы.

| Поток       | Что делает                                 |
| ----------- | ------------------------------------------ |
| `kworker`   | выполняет задачи из `workqueue`            |
| `ksoftirqd` | выполняет отложенную обработку [[softirq]] |
| `kthreadd`  | создаёт и управляет kernel threads         |
| `rcu*`      | обслуживает механизм RCU                   |

Не вся отложенная работа ядра выполняется через `kworker`. В Linux также используются `softirq`, таймеры, RCU и другие механизмы.

## Кратко

```text
Событие
   ↓
Ядро
   ↓
Срочную работу выполняет сразу
   ↓
Несрочную работу кладёт в workqueue
   ↓
kworker забирает её
   ↓
Выполняет в фоне
```

**`workqueue`** - очередь отложенной работы ядра.

**`kworker`** - поток ядра, который выполняет работу из этой очереди.

Это позволяет ядру быстро обрабатывать критические события и переносить менее срочную или более тяжёлую работу на потом.
