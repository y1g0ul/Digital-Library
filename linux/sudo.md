Система в [[Linux]] для запуска команд от имени другого пользователя, чаще всего `root`, с учётом правил из `/etc/sudoers`.

```bash
sudo [ключи] <команда>
```

|Ключ|Что делает|
|---|---|
|`-u <user>`|выполнить команду от имени пользователя|
|`-g <group>`|выполнить команду от имени группы|
|`-i`|открыть полноценный login shell|
|`-s`|открыть shell с повышенными правами|
|`-l`|показать разрешённые sudo-команды|
|`-k`|сбросить сохранённую авторизацию|
|`-v`|обновить sudo-сессию|
|`-E`|сохранить переменные окружения|

Примеры:
```bash
sudo apt update
# выполнить команду от root

sudo -u postgres psql
# выполнить команду от пользователя postgres

sudo -u petrov -g developer id
# выполнить команду с указанным UID и GID

sudo -l
# посмотреть доступные sudo-команды

sudo -i
# открыть полноценную root-сессию
```

## sudo -i

Создаёт **login shell root**, почти как прямой вход под `root`.

```text
HOME → /root
USER → root
рабочая директория → /root
окружение → окружение root
```

```bash
sudo -i
# получить полноценную root-сессию
```

Это обычно предпочтительнее, чем `sudo su`, если действительно нужна интерактивная root-сессия.

## su

`su` — переключает текущую оболочку на другого пользователя.

```bash
su <user>
```

В отличие от `sudo`, обычно требует пароль **целевого пользователя**.

```bash
su petrov
# переключиться на petrov

su -
# login shell root

su - petrov
# полноценный login shell пользователя petrov

su -c "id" petrov
# выполнить одну команду от petrov
```

Без `-` окружение частично сохраняется от текущего пользователя.

С `-` создаётся полноценный login shell целевого пользователя.

## sudo su

```bash
sudo su
```

Сначала `sudo` запускает команду `su` от root, после чего `su` открывает root-shell.

Пароль root при этом обычно не нужен - авторизацию выполняет `sudo`.

```text
sudo -i
→ сразу создаёт login shell root

sudo su
→ sudo запускает su, который затем создаёт shell root

sudo su -
→ примерно соответствует полноценному login shell root
```

Обычно для root-сессии проще использовать:
```bash
sudo -i
```

## sudoers

Правила доступа хранятся в:
```text
/etc/sudoers
/etc/sudoers.d/
```

Редактировать следует через:
```bash
visudo
# открыть sudoers с проверкой синтаксиса
```

Общий формат правила:
```text
USER HOST=(RUNAS_USER:RUNAS_GROUP) COMMAND
```

Пример:
```text
user ALL=(ALL:ALL) ALL
```

|Поле|Значение|
|---|---|
|`user`|кому выдаётся право|
|`ALL`|на каких хостах действует правило|
|`(ALL:ALL)`|от имени каких пользователей и групп можно запускать|
|`ALL`|какие команды разрешены|

Для группы используется `%`:

```text
%sudo ALL=(ALL:ALL) ALL
```

Это означает, что пользователи группы `sudo` могут выполнять любые команды от имени любого пользователя и группы.

## NOPASSWD

Позволяет выполнять определённую команду без запроса пароля:

```text
user ALL=(root) NOPASSWD: /usr/sbin/shutdown
```

Для группы:

```text
%admins ALL=(root) NOPASSWD: /usr/bin/systemctl restart nginx
```

Для разрешённых команд желательно указывать **полный путь** к исполняемому файлу.

## sudo и su

|Команда|Что делает|
|---|---|
|`sudo command`|выполнить одну команду с другими правами|
|`sudo -u user command`|выполнить команду от другого пользователя|
|`sudo -i`|полноценная root-сессия|
|`su user`|переключиться на пользователя, сохранив часть окружения|
|`su - user`|полноценный login shell пользователя|
|`sudo su`|открыть root-shell через `su`|

Главная идея:

```text
sudo
→ выдаёт контролируемые привилегии по правилам sudoers

su
→ переключает пользователя

sudoers
→ определяет кто, от чьего имени и какие команды может запускать
```
