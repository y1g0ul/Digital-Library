Встроенная команда shell в [[Linux]] для просмотра и изменения лимитов ресурсов текущего процесса и процессов, которые он запускает.
- Soft limit - текущий рабочий лимит процесса (обычно 1024).
- Hard limit - максимальное значение, до которого пользователь может поднять soft limit без дополнительных прав (обычно 4096).

```bash
ulimit [ключ] [значение]
```

|Ключ|Что ограничивает|
|---|---|
|`-n`|количество открытых файлов / файловых дескрипторов|
|`-u`|количество процессов пользователя|
|`-c`|размер core dump|
|`-f`|максимальный размер создаваемого файла|
|`-s`|размер стека|
|`-v`|виртуальная память|
|`-a`|показать все лимиты|
|`-S`|soft limit|
|`-H`|hard limit|

```text
Hard limit
    ↓
Soft limit
    ↓
текущее использование
```

Примеры:
```bash
ulimit -a
# показать все лимиты

ulimit -n
# показать лимит файловых дескрипторов

ulimit -n 65535
# установить soft limit FD для текущего shell

ulimit -Sn
# показать soft limit FD

ulimit -Hn
# показать hard limit FD

ulimit -u
# показать лимит процессов пользователя

ulimit -c unlimited
# разрешить core dump без ограничения размера
```

Лимиты наследуются дочерними процессами:
```text
shell
  ↓
ulimit
  ↓
запущенное приложение
```

Поэтому изменение `ulimit` действует только на текущий shell и процессы, которые будут запущены из него.

Типичная ошибка:
```text
Too many open files
```

Проверка:
```bash
ulimit -n
# проверить лимит FD текущего shell

cat /proc/<PID>/limits
# посмотреть лимиты конкретного процесса
```

Для сервисов [[systemd]] лимиты обычно задаются отдельно:
```ini
LimitNOFILE=65535
```

в unit-файле или override-конфигурации сервиса.
