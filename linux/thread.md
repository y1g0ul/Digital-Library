Отдельная линия выполнения внутри [[процесс]]a.

Один процесс может содержать один или несколько потоков:
```text
Process
├── Thread 1
├── Thread 2
├── Thread 3
└── Thread 4
```

Потоки одного процесса обычно используют общие ресурсы:
- виртуальную память;
- открытые файлы;
- сокеты;
- окружение процесса.

Но у каждого потока есть своё состояние выполнения:
- регистры CPU;
- stack;
- instruction pointer;
- состояние `running`, `runnable`, `sleeping` и т.д.

## Процесс и поток

Упрощённо:
```text
Process = контейнер ресурсов
Thread  = исполнитель внутри процесса
```

Например:
```text
Browser process
├── UI thread
├── network thread
├── rendering thread
└── background thread
```

Все потоки принадлежат одному процессу, но могут выполнять разные задачи.

## Многопоточность

Если процесс имеет несколько потоков, [[scheduler]] может выполнять их параллельно на разных логических CPU:
```text
Process
├── Thread 1 → CPU0
├── Thread 2 → CPU1
├── Thread 3 → CPU2
└── Thread 4 → CPU3
```

Однопоточный процесс:
```text
Process
└── Thread 1
```

в конкретный момент времени может выполняться только на одном логическом CPU.

## Scheduler и потоки

[[scheduler]] фактически распределяет CPU между задачами/потоками.

```text
Runnable threads
      ↓
  scheduler
      ↓
     CPU
```

Поэтому состояния вроде:
```text
running
runnable
sleeping
```

относятся к отдельным потокам выполнения.

## Почему потоки удобны

Потоки позволяют одному процессу:
- выполнять несколько задач одновременно;
- использовать несколько CPU;
- не блокировать всю программу из-за одной долгой операции;
- быстро обмениваться данными через общую память процесса.

Но из-за общей памяти между потоками могут возникать проблемы синхронизации, если несколько потоков одновременно изменяют одни и те же данные.

## Идентификация и просмотр потоков

В Linux каждый поток имеет собственный идентификатор **TID (Thread ID)**.

```
Process PID: 1500
├── Thread TID: 1500
├── Thread TID: 1501
├── Thread TID: 1502
└── Thread TID: 1503
```

Главный поток имеет TID, совпадающий с [[PID]] процесса.

Посмотреть потоки можно через [[ps]], [[top]] и /[[proc]].

|Команда|Что делает|
|---|---|
|`ps -eLf`|Показать все потоки системы|
|`ps -T -p PID`|Потоки конкретного процесса|
|`top -H`|Мониторинг отдельных потоков|
|`top -H -p PID`|Мониторинг потоков конкретного процесса|
|`ls /proc/PID/task/`|Список TID потоков процесса|

В выводе `ps` поле `LWP` соответствует TID, а `NLWP` показывает количество потоков процесса.

Информацию о конкретном потоке можно посмотреть через `/proc`:

```
cat /proc/1500/task/1501/status  # Состояние потока
cat /proc/1500/task/1501/sched   # Информация планировщика
```

Каждый поток планируется отдельно, поэтому можно управлять его приоритетом и привязкой к CPU:

```
renice -n 10 -p 1501  # Изменить nice потока
taskset -pc 2 1501    # Разрешить выполнение только на CPU2
```

**Важно:** потоки одного процесса разделяют ресурсы, но имеют собственные TID, состояния выполнения и параметры планирования.
## Кратко

```text
Программа
   ↓
Процесс
   ↓
один или несколько потоков
   ↓
Scheduler
   ↓
CPU
```

> **Thread - отдельный поток выполнения внутри процесса. Потоки одного процесса разделяют большую часть ресурсов, но каждый имеет собственное состояние выполнения и может отдельно планироваться scheduler'ом.**
