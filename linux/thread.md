Отдельная линия выполнения внутри [[процесс]]a.

Один процесс может содержать один или несколько потоков:
```text
Process
├── Thread 1
├── Thread 2
├── Thread 3
└── Thread 4
```

Потоки одного процесса обычно используют общие ресурсы:
- виртуальную память;
- открытые файлы;
- сокеты;
- окружение процесса.

Но у каждого потока есть своё состояние выполнения:
- регистры CPU;
- stack;
- instruction pointer;
- состояние `running`, `runnable`, `sleeping` и т.д.

## Процесс и поток

Упрощённо:
```text
Process = контейнер ресурсов
Thread  = исполнитель внутри процесса
```

Например:
```text
Browser process
├── UI thread
├── network thread
├── rendering thread
└── background thread
```

Все потоки принадлежат одному процессу, но могут выполнять разные задачи.

## Многопоточность

Если процесс имеет несколько потоков, [[scheduler]] может выполнять их параллельно на разных логических CPU:
```text
Process
├── Thread 1 → CPU0
├── Thread 2 → CPU1
├── Thread 3 → CPU2
└── Thread 4 → CPU3
```

Однопоточный процесс:
```text
Process
└── Thread 1
```

в конкретный момент времени может выполняться только на одном логическом CPU.

## Scheduler и потоки

[[scheduler]] фактически распределяет CPU между задачами/потоками.

```text
Runnable threads
      ↓
  scheduler
      ↓
     CPU
```

Поэтому состояния вроде:
```text
running
runnable
sleeping
```

относятся к отдельным потокам выполнения.

## Почему потоки удобны

Потоки позволяют одному процессу:
- выполнять несколько задач одновременно;
- использовать несколько CPU;
- не блокировать всю программу из-за одной долгой операции;
- быстро обмениваться данными через общую память процесса.

Но из-за общей памяти между потоками могут возникать проблемы синхронизации, если несколько потоков одновременно изменяют одни и те же данные.

## Кратко

```text
Программа
   ↓
Процесс
   ↓
один или несколько потоков
   ↓
Scheduler
   ↓
CPU
```

> **Thread - отдельный поток выполнения внутри процесса. Потоки одного процесса разделяют большую часть ресурсов, но каждый имеет собственное состояние выполнения и может отдельно планироваться scheduler'ом.**
