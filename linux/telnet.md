Команда в [[Linux]] для подключения к удалённому хосту по протоколу Telnet.

Сегодня сам протокол Telnet почти не используют для удалённого администрирования, потому что он передаёт данные без шифрования. Для этого используют [[SSH]].

Но `telnet` всё ещё полезен как простой способ проверить доступность TCP-порта.

```
telnet <host> <port>
```

### Примеры

```
telnet example.com 80
# проверить подключение к TCP-порту 80

telnet 192.168.1.10 22
# проверить, доступен ли SSH-порт

telnet mail.example.com 25
# подключиться к SMTP-порту
```

Если соединение установилось:
```
Connected to 192.168.1.10.
```

Это означает:
```
DNS/IP работает
→ маршрут есть
→ TCP-соединение установлено
→ порт доступен
```

Если получаем:
```
Connection refused
```

обычно это значит:
```
хост доступен
→ но на этом порту никто не слушает
или соединение активно отклоняется
```

Если соединение долго висит:
```
Connecting...
```

возможные причины:
- firewall делает `DROP`;
- проблемы с маршрутизацией;
- хост недоступен;
- порт фильтруется.

### Проверка HTTP вручную

После подключения:
```
telnet example.com 80
```

можно вручную отправить HTTP-запрос:
```
GET / HTTP/1.1
Host: example.com
```

После `Host:` нужна пустая строка.

Сервер вернёт HTTP-ответ.

### Выход из telnet

Обычно:
```
Ctrl + ]
```

после этого:
```
telnet> quit
```

### Telnet как протокол

Telnet исторически использовался для удалённого терминального доступа.

Стандартный порт:
```
TCP 23
```

Но логины, пароли и команды передаются без шифрования:
```
Telnet
→ данные открытым текстом ❌

SSH
→ зашифрованное соединение ✅
```

Поэтому для удалённого администрирования:
```
Telnet → устарел
SSH    → стандарт
```

### telnet и nc

Для простой проверки портов сегодня чаще используют [[nc]]:
```
nc -vz 192.168.1.10 22
# проверить TCP-порт 22
```

Упрощённо:
```
telnet host port
→ установить TCP-соединение
→ проверить, отвечает ли сервис
```

Главная идея: **Telnet как протокол устарел, но команда** `**telnet**` **может быть полезна для простой ручной проверки TCP-сервисов.**
