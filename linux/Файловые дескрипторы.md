Это целое число, которым процесс в [[Linux]] обозначает открытый файл, сокет, pipe, терминал или другой объект ввода-вывода.

Когда программа открывает файл, ядро возвращает ей номер дескриптора:
```text
процесс
  |
  ├── FD 0 → stdin
  ├── FD 1 → stdout
  ├── FD 2 → stderr
  ├── FD 3 → файл
  └── FD 4 → socket
```

Стандартные дескрипторы:

| FD  | Назначение                        |
| --- | --------------------------------- |
| `0` | stdin - стандартный ввод          |
| `1` | stdout - стандартный вывод        |
| `2` | stderr - стандартный поток ошибок |

Пример перенаправления:
```bash
command > file.txt
# stdout (FD 1) записать в файл

command 2> error.log
# stderr (FD 2) записать в файл

command > file.txt 2>&1
# stdout и stderr записать в один файл
```

Каждый процесс имеет собственную таблицу файловых дескрипторов.

Посмотреть дескрипторы процесса:
```bash
ls -l /proc/<PID>/fd
# показать открытые FD процесса
```

Например:
```text
0 -> /dev/pts/0
1 -> /dev/pts/0
2 -> /dev/pts/0
3 -> /var/log/app.log
4 -> socket:[12345]
```

Посмотреть открытые файлы ([[lsof]]):
```bash
lsof
# показать открытые файлы всей системы

lsof -p 1234
# показать FD процесса

lsof /var/log/app.log
# узнать, какой процесс держит файл открытым
```

## Лимиты

Количество файловых дескрипторов ограничено ([[ulimit]]).
```bash
ulimit -n
# лимит открытых FD для текущего процесса, обычно 1024 soft? 4096 hard.

cat /proc/sys/fs/file-max
# системный лимит открытых файлов
```

Если процесс исчерпал лимит, можно получить ошибку:
```text
Too many open files
```

Частые причины:
- слишком много сетевых соединений;
- приложение не закрывает файлы или сокеты;
- слишком низкий `ulimit`.

Главная идея:
```text
Файл / сокет / pipe
        ↓
      open()
        ↓
Ядро создаёт объект
        ↓
Процесс получает номер FD
        ↓
read() / write() / close()
```

Файловый дескриптор - это не сам файл, а **ссылка процесса на открытый объект ядра**.
