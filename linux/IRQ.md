Аппаратный запрос на прерывание, который сообщает CPU, что устройство требует внимания.

Например:
- сетевая карта получила пакет;
- диск закончил операцию;
- нажата клавиша;
- USB-устройство отправило событие.

Упрощённо:
```text
CPU выполняет обычную задачу
        ↓
приходит IRQ
        ↓
CPU временно прерывает текущую работу
        ↓
переходит в kernel mode
        ↓
запускается interrupt handler
        ↓
обрабатывается срочная часть события
```

Главная идея:
> **IRQ - это сигнал от аппаратного устройства к CPU.**

## Зачем нужен IRQ

Без прерываний CPU пришлось бы постоянно проверять устройства:
```text
"диск готов?"
"а сейчас?"
"а сейчас?"
```

Это называется polling.

С IRQ устройство само сообщает:
```text
"я закончил, обработай меня"
```

## Interrupt handler

Когда приходит IRQ, ядро запускает обработчик прерывания.

Он должен работать как можно быстрее.

Поэтому обычно:
```text
IRQ
 ↓
быстрая обработка
 ↓
остальная работа откладывается
```

Например сетевой пакет:
```text
NIC
 ↓
IRQ
 ↓
interrupt handler
 ↓
быстро фиксирует событие
 ↓
дальнейшая обработка
```

## Просмотр IRQ

```bash
cat /proc/interrupts
```

Там можно увидеть количество прерываний по CPU и устройства, которые их генерируют.

Например:
```text
           CPU0    CPU1    CPU2
24:        1200    3400    2200   eth0
```

## Кратко

```text
Hardware
   ↓
  IRQ
   ↓
CPU
   ↓
interrupt handler
```

> **IRQ - механизм, с помощью которого железо сообщает ядру о событии.**
