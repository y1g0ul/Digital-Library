Команда в [[Linux]] из пакета `lm_sensors` для просмотра данных аппаратных датчиков.

Обычно показывает:
- температуру CPU/GPU/SSD
- напряжения
- ток
- мощность
- обороты вентиляторов, если они доступны системе

```bash
sensors [ключи]
```

Основные команды:
```bash
sensors
# показать все доступные датчики

sensors -u
# показать сырые значения датчиков

sensors -A
# не показывать имя адаптера
```

Перед первым использованием иногда запускают:
```bash
sudo sensors-detect
# попытаться найти поддерживаемые датчики и нужные драйверы
```

Но на ноутбуках часть датчиков может уже работать через драйверы ядра даже если `sensors-detect` ничего не нашёл.

Пример:
```text
k10temp-pci-00c3
Tctl: +65.0°C

nvme-pci-0200
Composite: +44.9°C

amdgpu-pci-0300
vddgfx: 1.31 V
edge: +52.0°C
PPT: 8.00 W
```

Расшифровка:

|Поле|Что значит|
|---|---|
|`Tctl`|температура CPU AMD|
|`Composite`|основная температура NVMe|
|`edge`|температура GPU|
|`vddgfx`|напряжение GPU|
|`vddnb`|напряжение SoC/Northbridge|
|`PPT`|потребляемая мощность|
|`fan1`|обороты вентилятора|
|`in0`|напряжение|
|`curr1`|ток|

`sensors` получает данные через аппаратные драйверы ядра и интерфейс [[sys|sysfs]]:
```text
железо
→ драйвер ядра
→ /sys/class/hwmon/
→ sensors
```

Посмотреть доступные hwmon-устройства:
```bash
ls /sys/class/hwmon/
# список hwmon-устройств

cat /sys/class/hwmon/hwmon*/name
# показать их имена
```

Полезно для мониторинга:
```bash
watch -n 1 sensors
# обновлять показания каждую секунду
```

Важно: если `fan1`, напряжение или другой датчик отсутствует, это не обязательно означает отсутствие самого датчика. Производитель ноутбука может не предоставлять его Linux через стандартный интерфейс.
