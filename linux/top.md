Команда в [[Linux]] для мониторинга [[процесс]]ов и состояния системы в реальном времени. Показывает нагрузку, [[Load Average]], CPU, RAM, [[Swap]] и ресурсы отдельных [[процесс]]ов.      

```bash
top [ключи]
```

## Общая информация

Пример:
```text
top - 10:41:23 up 1:40, 1 user, load average: 1,30, 1,14, 0,85
```

|Поле|Что означает|
|---|---|
|`10:41:23`|текущее время|
|`up 1:40`|система работает 1 час 40 минут|
|`1 user`|количество вошедших пользователей|
|`load average`|средняя нагрузка за 1, 5 и 15 минут|

```text
load average: 1.30, 1.14, 0.85
              │     │     │
              1m    5m    15m
```

[[Load Average]] - не процент CPU, а количество задач, которые выполняются или ожидают CPU / непрерываемый I/O.

---

## Задачи

```text
Tasks: 381 total, 2 running, 379 sleeping, 0 d-sleep, 0 stopped, 0 zombie
```

| Поле       | Что означает                                                           |
| ---------- | ---------------------------------------------------------------------- |
| `total`    | всего процессов/задач                                                  |
| `running`  | выполняются или готовы выполняться                                     |
| `sleeping` | ожидают событие, таймер, ввод и т.д.                                   |
| `d-sleep`  | количество процессов в состоянии `D`, то есть `uninterruptible sleep`. |
| `stopped`  | остановленные процессы                                                 |
| `zombie`   | завершённые процессы, родитель которых ещё не забрал код завершения    |

Большое количество `sleeping` — нормально. Большинство процессов большую часть времени чего-либо ждут.

## CPU

```text
%Cpu(s): 1.7 us, 1.1 sy, 0.0 ni, 97.1 id, 0.1 wa, 0.0 hi, 0.0 si, 0.0 st
```

| Поле | Что означает                                                                                                                                                   |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `us` | работа пользовательских программ                                                                                                                               |
| `sy` | работа ядра Linux                                                                                                                                              |
| `ni` | процессы с изменённым [[nice]]                                                                                                                                 |
| `id` | простой CPU                                                                                                                                                    |
| `wa` | ожидание операций ввода-вывода (Это состояние, когда процессор ждет, пока медленное устройство (диск, сеть, клавиатура) передаст или примет данные.)           |
| `hi` | обработка аппаратных прерываний (Это сигнал процессору от физического устройства (клавиатуры, мыши, сетевой карты, таймера), что ему требуется внимание.)      |
| `si` | обработка программных прерываний (Cигнал процессору, который инициируется самой программой (или кодом операционной системы) с помощью специальной инструкции.) |
| `st` | CPU-время, забранное гипервизором у виртуальной машины                                                                                                         |

Например:
```text
97.1 id
```

означает, что CPU почти не загружен.

Высокий `wa` может указывать на проблемы или высокую нагрузку дисковой подсистемы → [[iostat]], [[iotop]].

Высокий `sy` означает, что много CPU-времени тратится внутри ядра.

## RAM

```text
MiB Mem : 15351.8 total, 7040.1 free, 5935.1 used, 2997.9 buff/cache
```

|Поле|Что означает|
|---|---|
|`total`|всего RAM|
|`free`|полностью свободная RAM|
|`used`|используемая память|
|`buff/cache`|память, используемая ядром под буферы и файловый кэш|

Linux специально использует свободную RAM под кэш, поэтому маленькое значение `free` само по себе не означает нехватку памяти.

Более полезный показатель:
```text
avail Mem: 9416.6
```

`avail Mem` - примерная память, которую можно выделить новым программам без активного использования Swap.

---

## Swap

```text
MiB Swap: 4096.0 total, 4096.0 free, 0.0 used
```

|Поле|Что означает|
|---|---|
|`total`|размер Swap|
|`free`|свободный Swap|
|`used`|используемый Swap|

Небольшое использование Swap не обязательно является проблемой. Постоянный активный обмен RAM ↔ Swap может говорить о нехватке памяти.

## Процессы

```text
PID USER   PR NI   VIRT    RES    SHR S %CPU %MEM TIME+
3461 y1g0ul 20 0 6011440 420156 166984 S 16.8  2.7  8:15.78
```

| Поле      | Что означает                                                |
| --------- | ----------------------------------------------------------- |
| `PID`     | ID процесса                                                 |
| `USER`    | владелец процесса                                           |
| `PR`      | приоритет планировщика                                      |
| `NI`      | значение [[nice]]                                           |
| `VIRT`    | всё виртуальное адресное пространство процесса              |
| `RES`     | физическая RAM, находящаяся сейчас в памяти                 |
| `SHR`     | часть памяти, потенциально разделяемая с другими процессами |
| `S`       | состояние процесса                                          |
| `%CPU`    | использование CPU                                           |
| `%MEM`    | доля RAM                                                    |
| `TIME+`   | суммарное CPU-время процесса                                |
| `COMMAND` | команда/процесс                                             |

### VIRT, RES и SHR

```text
VIRT
└── всё виртуальное адресное пространство

RES
└── то, что реально находится в RAM

SHR
└── часть RES, которая может использоваться совместно
```

Для оценки фактического потребления RAM обычно в первую очередь смотрят на `RES` и `%MEM`.

Очень большой `VIRT` не обязательно означает проблему. Программа может зарезервировать огромный диапазон виртуальных адресов, практически не используя физическую RAM.

Например:
```text
VIRT = 1448G
RES  = 467M
```

не означает, что процесс занимает 1.4 TB RAM. Реально в памяти находится около `467 MB`.

## Состояние процесса (`S`)

| Значение | Состояние                                                                                                                                       |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `R`      | Running - выполняется или готов к выполнению                                                                                                    |
| `S`      | Sleeping - обычное ожидание                                                                                                                     |
| `D`      | непрерываемое ожидание, обычно I/O                                                                                                              |
| `T`      | остановлен                                                                                                                                      |
| `Z`      | Zombie - процесс завершился, но ещё не обработан родителем                                                                                      |
| `I`      | idle kernel thread (специальный системный поток, который запускается операционной системой, когда процессор не занят выполнением других задач.) |

Большое количество процессов в `D` может указывать на проблемы с диском, сетью или другим I/O.

## Приоритет

`NI` - значение [[nice]]:
```text
-20 ← высокий приоритет
  0 ← обычный
 19 ← низкий
```

`PR` - Фактический приоритет, который ядро Linux использует при планировании задач. Как правило, он вычисляется на основе значения [[nice]]. По умолчанию для обычных процессов значение `PRI` рассчитывается как [[nice]] + 20

Изменить nice запущенного процесса можно через:
```bash
renice 10 -p 1234
```

## Управление внутри top

|Клавиша|Что делает|
|---|---|
|`P`|сортировать по `%CPU`|
|`M`|сортировать по `%MEM`|
|`T`|сортировать по `TIME+`|
|`N`|сортировать по PID|
|`1`|показать каждый логический CPU отдельно|
|`k`|отправить сигнал процессу|
|`r`|изменить nice процесса|
|`c`|показать полную командную строку|
|`H`|показать отдельные потоки|
|`f`|выбрать отображаемые поля|
|`q`|выйти|

## Примеры
```bash
top
# открыть мониторинг

top -p 1234
# следить только за PID 1234

top -u user
# показать процессы пользователя

top -d 2
# обновлять каждые 2 секунды

top -b -n 1
# один снимок состояния системы, удобно для скриптов

top -b -n 1 | head -20
# быстро получить общую информацию о системе
```

При диагностике обычно смотрят:
```text
load average  → есть ли очередь задач
us / sy       → куда уходит CPU
wa            → ждёт ли система I/O
avail Mem     → достаточно ли RAM
Swap used     → используется ли Swap
%CPU          → кто нагружает процессор
RES / %MEM    → кто занимает RAM
S             → в каком состоянии процесс
```
