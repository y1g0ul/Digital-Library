**DNF (Dandified YUM)** - пакетный менеджер в [[Linux]] для установки, обновления, удаления и поиска программ.

Используется в Fedora, RHEL и родственных дистрибутивах. На современных версиях Fedora используется **DNF5**.

```
dnf [ключи] <команда> [пакет]
```

### Основные команды

|Команда|Что делает|
|---|---|
|`install`|установить пакет|
|`remove`|удалить пакет|
|`autoremove`|удалить больше не нужные зависимости|
|`upgrade`|обновить установленные пакеты|
|`check-upgrade`|проверить наличие обновлений|
|`search`|найти пакет по названию или описанию|
|`info`|подробная информация о пакете|
|`list`|список пакетов|
|`reinstall`|переустановить пакет|
|`provides`|найти пакет, которому принадлежит файл или команда|
|`repoquery`|получить информацию о пакетах и зависимостях|
|`history`|история операций с пакетами|

### Основные примеры

``` bash
sudo dnf install nginx
# установить nginx

sudo dnf remove nginx
# удалить nginx

sudo dnf autoremove
# удалить ненужные зависимости

sudo dnf upgrade
# обновить установленные пакеты

dnf check-upgrade
# проверить доступные обновления

dnf search nginx
# найти пакет

dnf info nginx
# подробная информация о пакете

dnf list --installed
# показать установленные пакеты

sudo dnf reinstall nginx
# переустановить пакет
```

### Поиск пакетов

Полезная возможность - найти пакет, который предоставляет определённый файл или команду.

```
dnf provides /usr/bin/htop
# узнать, какому пакету принадлежит файл

dnf provides '*/ifconfig'
# найти пакет, предоставляющий ifconfig

dnf repoquery --requires nginx
# показать зависимости nginx
```

Например, если ты вводишь незнакомую команду и получаешь `command not found`, через `dnf provides` можно найти пакет, который необходимо установить.

### Репозитории

**Repository (репозиторий)** - источник, из которого DNF получает пакеты и информацию об обновлениях.

```
Fedora repositories
        ↓
       DNF
        ↓
разрешение зависимостей
        ↓
установка RPM-пакетов
```

| Команда               | Что делает                          |
| --------------------- | ----------------------------------- |
| `dnf repo list`       | показать включённые репозитории     |
| `dnf repo list --all` | показать все репозитории            |
| `dnf repo info`       | подробная информация о репозиториях |
| `dnf makecache`       | обновить локальный кеш метаданных   |
| `dnf clean all`       | очистить кеш DNF                    |

Примеры:
``` bash
dnf repo list
# показать подключённые репозитории

dnf repo list --all
# показать также отключённые репозитории

sudo dnf makecache
# обновить метаданные репозиториев

sudo dnf clean all
# очистить кеш
```

Основные конфигурационные файлы:
``` bash
/etc/dnf/dnf.conf
# основная конфигурация DNF

/etc/yum.repos.d/
# конфигурации репозиториев
```

### История операций

DNF сохраняет историю транзакций - установки, удаления и обновления пакетов.

``` bash
dnf history list
# показать историю операций

dnf history info 15
# подробности транзакции №15

sudo dnf history undo 15
# попытаться отменить транзакцию №15
```

Отмена транзакции не всегда возможна, например если старые версии пакетов уже недоступны.

### DNF и RPM

Важно понимать разницу между двумя инструментами:

| Инструмент | Назначение                                         |
| ---------- | -------------------------------------------------- |
| [[rpm]]    | низкоуровневая работа с RPM-пакетами               |
| `dnf`      | управление пакетами, репозиториями и зависимостями |

```
dnf
 ├── получает метаданные из репозиториев
 ├── ищет нужные пакеты
 ├── разрешает зависимости
 └── устанавливает RPM-пакеты
```

Например:
```
sudo rpm -i nginx.rpm
# установить локальный RPM напрямую

sudo dnf install ./nginx.rpm
# установить локальный RPM с разрешением зависимостей
```
