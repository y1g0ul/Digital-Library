Команда в [[Linux]] которая позволяет отправить [[сигнал]] [[процесс]]у

Чаще всего используется, чтобы попросить процесс завершиться или принудительно его остановить.

```
kill [сигнал] <PID>
```

Важно: `kill` не обязательно «убивает» процесс. Она просто отправляет ему сигнал.

### Основные сигналы

|Сигнал|Номер|Что делает|
|---|---|---|
|`SIGTERM`|`15`|корректно попросить процесс завершиться|
|`SIGKILL`|`9`|немедленно завершить процесс|
|`SIGHUP`|`1`|часто используется для перечитывания конфигурации|
|`SIGINT`|`2`|аналог `Ctrl+C`|
|`SIGSTOP`|`19`|приостановить процесс|
|`SIGCONT`|`18`|продолжить остановленный процесс|

По умолчанию:
```
kill 1234
```

это то же самое, что:
```
kill -TERM 1234
```

или
```
kill -15 1234
```

### Примеры

```
kill 1234
# попросить процесс 1234 корректно завершиться

kill -TERM 1234
# то же самое явно через SIGTERM

kill -9 1234
# принудительно завершить процесс

kill -STOP 1234
# приостановить процесс

kill -CONT 1234
# продолжить выполнение

kill -HUP 1234
# отправить SIGHUP
```

### Посмотреть сигналы

```
kill -l
# показать список сигналов
```

Например:
```
1  SIGHUP
2  SIGINT
9  SIGKILL
15 SIGTERM
18 SIGCONT
19 SIGSTOP
```

### SIGTERM и SIGKILL

Обычно сначала используют:
```
kill PID
```

`SIGTERM` даёт программе возможность:
- закрыть файлы;
- сохранить данные;
- завершить соединения;
- корректно освободить ресурсы.

Если процесс не реагирует:
```
kill -9 PID
```

`SIGKILL` обрабатывается ядром и не может быть проигнорирован процессом.

Поэтому:
```
SIGTERM
→ нормальное завершение

SIGKILL
→ аварийное принудительное завершение
```

### Как найти PID

```
ps aux | grep nginx
# найти процесс

pgrep nginx
# получить PID процесса по имени
```

После этого:
```
kill 1234
```

### Связанные команды

[[pkill]] → отправить сигнал процессам по имени/условию

Например:
```
pkill nginx
# отправить SIGTERM процессам nginx

pkill -9 nginx
# принудительно завершить процессы nginx
```

Главная идея:
```
процесс
   ↑
 сигнал
   ↑
 kill
```

`kill` - это интерфейс для отправки сигналов процессам, а не просто команда принудительного завершения.

> [!info] Почему команда называется `kill`, если она просто отправляет сигнал?
>#### Немного истории UNIX:
>В ранних версиях Unix действительно была команда `kill`, которая использовалась только для завершения [[процесс]]ов.
>
>То есть: `kill PID` = «Убей [[процесс]]».
>Это отправляло [[сигнал]] по умолчанию → `SIGTERM` (мягкое завершение).
>
>С развитием системы [[сигнал]]ов, оказалось, что [[сигнал]]ы бывают не только «убей»,но и «поставь на паузу», «перезапусти», «ничего не делай», «просто проверь» и т.д. 
>Тогда стало логично - пусть команда `kill` может отправлять любой [[сигнал]], не только «убивающий».
>##### UNIX и [[Linux]] устроены так:
**Никогда не ломай совместимость.**
Если в 1970-х появилась команда `kill`, а ты через неё управлял [[процесс]]ами в своих скриптах, то спустя 50 лет эта команда должна работать точно так же, иначе твои скрипты сломаются.
