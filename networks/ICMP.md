Internet Control Message Protocol - служебный протокол, который используется устройствами сети для передачи сообщений об ошибках и состоянии сети. Он не передаёт пользовательские данные как [[TCP]] или [[UDP]], а помогает понять, что происходит с [[networks/IP|IP]]-пакетами.

Заголовок:
1. Тип сообщения
2. Код сообщения
3. Контрольная сумма
4. Служебная информация

Примеры:
```text
узел недоступен
время жизни пакета закончилось
нужно проверить доступность устройства
```

Команда [[ping]] использует ICMP:
```bash
ping 8.8.8.8
```

Отправитель посылает:
```text
ICMP Echo Request
```

Получатель отвечает:
```text
ICMP Echo Reply
```

Схематично:
```text
Host A                      Host B

Echo Request  ------------->

              <------------- Echo Reply
```

По времени между запросом и ответом можно примерно определить задержку сети.

## Destination Unreachable

Если пакет невозможно доставить, устройство может вернуть:
```text
Destination Unreachable
```

Например:
```text
Host
 ↓
Router
 ↓
нужная сеть недоступна
 ↓
ICMP Destination Unreachable
 ↓
Host
```

Причины могут быть разными:
- сеть недоступна;
- хост недоступен;
- порт недоступен;
- пакет невозможно доставить по другой причине.

Например, если отправить UDP-датаграмму на закрытый [[ports|порт]], получатель может ответить ICMP-сообщением:
```text
Port Unreachable
```

## Time Exceeded

В каждом IP-пакете есть поле `TTL`.

Каждый роутер уменьшает его значение:
```text
TTL 3
 ↓ Router
TTL 2
 ↓ Router
TTL 1
 ↓ Router
TTL 0
```

Когда TTL становится равен `0`, роутер отбрасывает пакет и обычно отправляет:
```text
ICMP Time Exceeded
```

Этот механизм используется командой [[traceroute]]. Благодаря этому можно увидеть, через какие маршрутизаторы проходит трафик.

## ICMP Redirect

Роутер может сообщить хосту, что существует более подходящий маршрут.

Например:
```text
Host
 ↓
Router A
 ↓
Router B
```

Router A может сказать:
```text
Лучше отправляй такие пакеты сразу через Router B
```

Для этого используется:
```text
ICMP Redirect
```

## ICMP и порты

В отличие от TCP и UDP, ICMP не использует порты.

```text
TCP → порты
UDP → порты
ICMP → типы сообщений и коды
```

Например:
```text
Echo Request
Echo Reply
Destination Unreachable
Time Exceeded
```

Каждое ICMP-сообщение имеет свой тип, а иногда ещё и дополнительный код, уточняющий причину.

## ICMP и IP

ICMP передаётся внутри IP-пакета.

Упрощённо:
```text
Ethernet
   ↓
IP
   ↓
ICMP
```

То есть ICMP работает вместе с IP и используется для служебного обмена информацией между узлами и маршрутизаторами.

## Важно

ICMP - это не только `ping`.

`ping` использует лишь два типа ICMP-сообщений:
```text
Echo Request
Echo Reply
```

Сам ICMP также используется для:
- сообщений об ошибках;
- диагностики сети;
- работы traceroute;
- уведомлений о проблемах с маршрутизацией.

## Кратко

```text
ICMP
 │
 ├─ проверка доступности
 ├─ сообщения об ошибках
 ├─ диагностика сети
 ├─ Time Exceeded
 ├─ Destination Unreachable
 └─ не использует порты
```

Главная идея:
```text
IP передаёт пакеты,
а ICMP помогает сообщить,
что с этими пакетами произошло.
```
