Open Shortest Path First - протокол динамической маршрутизации, который помогает роутерам автоматически обмениваться информацией о сетях и выбирать лучший маршрут.

Используется **внутри одной автономной системы**, например внутри сети компании или провайдера.

```text
Router A ── Router B ── Router C
   \                      /
    ─────── Router D ─────
```

OSPF позволяет каждому роутеру понять:
```text
Какие сети существуют?
Через кого до них идти?
Какой маршрут лучше?
```

## Как работает

Роутеры OSPF обмениваются информацией о своих соединениях.

Например:
```text
Router A знает:

сеть 10.0.1.0/24
сосед Router B
сосед Router D
```

Router A сообщает это другим OSPF-роутерам.

В результате каждый роутер строит у себя карту сети.

```text
        Router B
       /        \
Router A        Router C
       \        /
        Router D
```

После этого он самостоятельно вычисляет лучший путь до каждой сети.

## Соседи

Сначала OSPF-роутеры должны обнаружить друг друга.

Для этого они отправляют:
```text
Hello
```

Примерно:
```text
Router A:
Я OSPF-роутер, кто рядом?

Router B:
Я тоже OSPF-роутер.
```

Если параметры совпадают, роутеры становятся соседями и начинают обмениваться информацией о маршрутах.

## Link-State

OSPF относится к протоколам типа:
```text
Link-State
```

Это значит, что роутеры распространяют информацию не просто в формате:
```text
До сети X идти через Router B
```

а сообщают состояние своих соединений:
```text
Router A связан с Router B
стоимость = 10

Router A связан с Router D
стоимость = 20
```

Из этой информации каждый роутер сам строит карту сети.

## LSDB

Информация о топологии хранится в:
```text
LSDB
Link-State Database
```

У роутеров внутри одной OSPF area должна быть согласованная информация о топологии.

Упрощённо:
```text
LSDB
 ↓
карта всей area
 ↓
расчёт лучших маршрутов
 ↓
routing table
```

## SPF

После построения карты сети OSPF запускает алгоритм:
```text
SPF
Shortest Path First
```

Он рассчитывает кратчайший путь от текущего роутера до остальных сетей.

Например:

```text
      B
 10 /    \  10
   /        \   
A ----------- C
 \           /
  \ 5     5 /
   \       /
      D
```

До C есть два варианта:

```text
A → B → C
стоимость 20

A → D → C
стоимость 10
```

OSPF выберет:
```text
A → D → C
```

## Cost

OSPF выбирает маршрут по специальной метрике:
```text
Cost
```

Чем меньше суммарный cost пути, тем лучше маршрут.
```text
Path 1:
Cost = 30

Path 2:
Cost = 10

OSPF выберет Path 2
```

Cost обычно связан со скоростью интерфейса, но его также можно настроить вручную.

## Area

Чтобы огромная сеть не превращалась в одну большую карту, OSPF позволяет разделять её на:
```text
Area
```

Например:
```text
Area 1
   │
   │
Area 0
   │
   │
Area 2
```

Главная область:
```text
Area 0
```

называется `backbone area`.

Другие области обычно соединяются через Area 0.

## Зачем нужны Area

Без разделения каждый роутер должен знать топологию всей огромной сети.

Area позволяет уменьшить:
- размер LSDB;
- количество служебного трафика;
- нагрузку на роутеры;
- количество пересчётов маршрутов.

Для маленькой сети часто достаточно:
```text
Area 0
```

## Изменение сети

Если соединение пропало:
```text
Router A ─X─ Router B
```

OSPF распространяет информацию об изменении.

Другие роутеры обновляют карту и пересчитывают маршруты.
```text
старый путь:
A → B → C

B недоступен

новый путь:
A → D → C
```

Это и есть одно из главных преимуществ динамической маршрутизации.

## OSPF и статические маршруты

Без OSPF администратор может вручную прописать:
```text
Чтобы попасть в 10.20.0.0/16
иди через 192.168.1.2
```

Это статический маршрут.

С OSPF роутеры могут узнать маршруты автоматически:
```text
Router A
  ↕
Router B
  ↕
Router C

OSPF сам распространяет
информацию о сетях
```

## OSPF и BGP

Упрощённо:
```text
OSPF
↓
маршрутизация внутри организации

BGP
↓
маршрутизация между автономными системами
```

Например:
```text
Сеть компании
      ↓
     OSPF

Компания ↔ Провайдер ↔ Internet
              ↓
             BGP
```

## Кратко

```text
OSPF
 │
 ├─ динамическая маршрутизация
 ├─ работает внутри автономной системы
 ├─ роутеры находят соседей через Hello
 ├─ обмениваются состоянием соединений
 ├─ строят LSDB
 ├─ используют SPF
 ├─ выбирают путь по Cost
 └─ большие сети делятся на Area
```

Главная идея:
```text
Роутеры обмениваются информацией о топологии
        ↓
каждый строит карту сети
        ↓
сам рассчитывает лучший маршрут
```
