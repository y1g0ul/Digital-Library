Протокол динамической маршрутизации, который позволяет роутерам автоматически обмениваться информацией о доступных сетях и выбирать маршруты.  Используется внутри одной автономной системы (`IGP`).

Исторически разработан Cisco и преимущественно используется на оборудовании этой компании.

## Как работает

Роутеры обнаруживают соседей и обмениваются информацией о доступных сетях.

Например:
```
          R2
         /  \
        /    \
      R1      R4 ── 10.0.4.0/24
        \    /
         \  /
          R3
```

R1 узнаёт, что до сети `10.0.4.0/24` можно добраться двумя путями:
```
R1 → R2 → R4

R1 → R3 → R4
```

EIGRP сравнивает маршруты и выбирает основной. Если подходящий резервный маршрут уже известен, он может быстро переключиться на него при отказе основного.

## Обнаружение соседей

Роутеры EIGRP используют сообщения:
```
Hello
```

Они позволяют находить соседей и проверять, что те продолжают работать.
```
Router A                    Router B

Hello --------------------->

      <--------------------- Hello
```

После установления соседства роутеры обмениваются маршрутной информацией.

В отличие от OSPF, EIGRP не строит полную карту всех соединений сети.

Он хранит информацию о доступных маршрутах, полученную от соседей.

## DUAL

Для выбора маршрутов EIGRP использует алгоритм:

`DUAL` (`Diffusing Update Algorithm`).

Он помогает выбирать маршруты без петель и находить резервные пути.

Для этого используются три важных понятия.

### Successor

`Successor` - основной маршрут, выбранный EIGRP.

Например:
```
        R2
       /
R1 ───       R4
       \
        R3

Основной путь:

R1 → R2 → R4
```

### Feasible Successor

`Feasible Successor` - заранее известный резервный маршрут, который удовлетворяет условию отсутствия петель.

Например:
```
Основной:
R1 → R2 → R4

Резервный:
R1 → R3 → R4
```

Если основной путь пропадёт, EIGRP сможет быстро переключиться на резервный без нового поиска по всей сети.

Важно: не каждый альтернативный маршрут автоматически становится Feasible Successor.

### Feasible Distance и Reported Distance

Для проверки маршрутов EIGRP использует две величины:

|Параметр|Значение|
|---|---|
|`Feasible Distance (FD)`|Известная минимальная стоимость пути от текущего роутера до сети|
|`Reported Distance (RD)`|Стоимость пути до сети, которую сообщает сосед|

Например:
```
R1 → R2 → Network

R1 до R2:       10
R2 до Network:  20

Общая стоимость: 30
```

Для R1:
```
RD = 20
FD = 30
```

Чтобы альтернативный путь мог считаться Feasible Successor, его RD должен быть меньше текущего FD основного маршрута.

Это условие помогает избежать петель маршрутизации.

## Метрика

EIGRP выбирает маршруты на основании специальной метрики.

По умолчанию при её расчёте учитываются:

- **Bandwidth** - минимальная пропускная способность на пути.
- **Delay** - суммарная задержка интерфейсов на пути.

Упрощённо:
```
Путь A:
высокая пропускная способность
небольшая задержка

Путь B:
низкая пропускная способность
большая задержка
```

EIGRP обычно предпочтёт путь A, если его рассчитанная метрика меньше.

Метрика EIGRP также может учитывать надёжность и загрузку соединений, если изменить настройки расчёта.

## Обновление маршрутов

EIGRP не отправляет соседям полную таблицу маршрутизации через одинаковые промежутки времени.

После первоначального обмена он передаёт информацию преимущественно при изменениях.

Например:
```
R1 ── R2 ── R3
```

Если соединение R2–R3 пропало:
```
R1 ── R2 ─X─ R3
```

R2 сообщает соседям об изменении.

Если подходящего резервного маршрута нет, DUAL может начать поиск нового пути, отправляя соседям специальные запросы.

Это позволяет уменьшить количество лишнего служебного трафика.

## Основные сообщения

|Сообщение|Назначение|
|---|---|
|`Hello`|Обнаружение соседей и проверка доступности|
|`Update`|Передача информации о маршрутах|
|`Query`|Поиск альтернативного маршрута|
|`Reply`|Ответ на запрос о маршруте|
|`ACK`|Подтверждение получения надёжно передаваемого EIGRP-сообщения|

EIGRP работает непосредственно поверх IP:
```
IP Protocol = 88
```

То есть он не использует TCP или UDP для передачи собственных сообщений.

## EIGRP и OSPF

Оба протокола используются для динамической маршрутизации внутри автономной системы, но работают по-разному.

|EIGRP|OSPF|
|---|---|
|Использует DUAL|Использует SPF|
|Хранит информацию о маршрутах от соседей|Строит карту топологии в LSDB|
|Метрика учитывает bandwidth и delay|Использует cost|
|Может заранее хранить резервный путь|Пересчитывает маршруты при изменениях топологии|
|Исторически связан с Cisco|Широко поддерживается разными производителями|

## Команды Cisco

Посмотреть соседей:
```
show ip eigrp neighbors
```

Посмотреть топологическую таблицу EIGRP:
```
show ip eigrp topology
```

Посмотреть маршруты EIGRP:
```
show ip route eigrp
```

## Кратко

```
EIGRP
 │
 ├─ динамическая маршрутизация
 ├─ работает внутри AS
 ├─ обнаруживает соседей через Hello
 ├─ использует алгоритм DUAL
 ├─ Successor → основной маршрут
 ├─ Feasible Successor → резервный маршрут
 ├─ учитывает bandwidth и delay
 └─ отправляет обновления при изменениях
```

Главная идея:
```
Роутеры обмениваются маршрутами
          ↓
DUAL выбирает основной путь
          ↓
Запоминает подходящие резервные пути
          ↓
При отказе основного пути
может быстро переключиться на резервный
```
