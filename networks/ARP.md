Протокол, который используется в [[IPv4]]-сетях для определения [[MAC]]-адреса по известному [[networks/IP|IP]]-адресу. Он нужен потому, что IP используется для логической адресации, а для передачи Ethernet-кадра внутри локальной сети нужен MAC-адрес получателя.

## Как работает

Допустим, компьютер:
```text
IP:  192.168.1.10
MAC: AA:AA:AA:AA:AA:AA
```

хочет отправить данные устройству:
```text
IP: 192.168.1.20
```

Но его MAC-адрес неизвестен.

Компьютер отправляет `ARP Request`:
```text
Кто имеет IP 192.168.1.20?

Ответьте устройству: IP 192.168.1.10 
MAC AA:AA:AA:AA:AA:AA
```

ARP Request отправляется широковещательно:
```text
Destination MAC:
FF:FF:FF:FF:FF:FF
```

Все устройства в локальной сети получают запрос, но отвечает только владелец нужного IP:
```text
ARP Reply:

192.168.1.20 находится по адресу
BB:BB:BB:BB:BB:BB
```

После этого компьютер может отправить обычный Ethernet-кадр:
```text
Source MAC:
AA:AA:AA:AA:AA:AA

Destination MAC:
BB:BB:BB:BB:BB:BB
```

## ARP cache

Чтобы не выполнять ARP-запрос перед каждым пакетом, операционная система временно сохраняет соответствия:

```text
IP → MAC
```

Например:
```text
192.168.1.1  →  00:11:22:33:44:55
192.168.1.20 →  BB:BB:BB:BB:BB:BB
```

Посмотреть таблицу соседей в Linux:
```bash
ip neigh
```

Пример:
```text
192.168.1.1 dev eth0 lladdr 00:11:22:33:44:55 REACHABLE
```

Также может встречаться старая команда:
```bash
arp -n
```

## Если устройство находится в другой сети

ARP не ищет MAC конечного удалённого сервера.

Например, компьютер:
```text
192.168.1.10
```

хочет обратиться к:
```text
8.8.8.8
```

Так как `8.8.8.8` находится в другой сети, компьютер определяет MAC своего **шлюза по умолчанию**:
```text
192.168.1.1 → MAC роутера
```

И Ethernet-кадр отправляется роутеру:
```text
Destination MAC: MAC роутера
Destination IP:  8.8.8.8
```

То есть:
```text
IP определяет конечного получателя пакета.
MAC определяет следующего получателя кадра в текущем сегменте сети.
```

## Важные особенности

- ARP работает только с `IPv4`.
- ARP работает в пределах локального broadcast-домена и не маршрутизируется через роутеры.
- `ARP Request` обычно является broadcast.
- `ARP Reply` обычно отправляется напрямую запрашивающему устройству.
- Для [[IPv6]] вместо ARP используется [[NDP]] (`Neighbor Discovery Protocol`).

## ARP spoofing

ARP не имеет встроенной аутентификации, поэтому устройство может отправить ложное соответствие:
```text
192.168.1.1 → MAC атакующего
```

Такую атаку называют `ARP spoofing` или `ARP poisoning`. Она может использоваться для проведения `Man-in-the-Middle` атак внутри локальной сети.s
