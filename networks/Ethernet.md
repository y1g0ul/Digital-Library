`Ethernet` - технология передачи данных в локальных сетях.

Она работает в основном на **канальном уровне** и определяет, как устройства передают друг другу кадры по сети.

Обычно Ethernet используется через витую пару или оптоволокно.

```text
PC
 ↓
Ethernet
 ↓
Switch
 ↓
Ethernet
 ↓
Server
```

## Ethernet-кадр

Данные передаются не напрямую, а внутри:
```text
Ethernet Frame
```

Упрощённо кадр выглядит так:
```text
┌──────────────────────┐
│ Destination MAC      │
├──────────────────────┤
│ Source MAC           │
├──────────────────────┤
│ EtherType            │
├──────────────────────┤
│ Data                 │
├──────────────────────┤
│ FCS                  │
└──────────────────────┘
```

## Destination MAC

[[MAC]]-адрес устройства, которому предназначен кадр.

Например:
```text
AA:BB:CC:DD:EE:FF
```

Switch смотрит именно на этот адрес, чтобы понять, через какой порт отправить кадр дальше.

## Source MAC

MAC-адрес устройства, которое отправило кадр.

Например:
```text
11:22:33:44:55:66
```

## EtherType

Показывает, какой протокол находится внутри Ethernet-кадра.

Например:
```text
0x0800 → IPv4
0x86DD → IPv6
0x0806 → ARP
```

Получатель благодаря этому понимает, как обработать содержимое кадра дальше.

## Data

Полезная нагрузка Ethernet.

Например, внутри может находиться:
```text
Ethernet
   ↓
IPv4
   ↓
TCP
   ↓
HTTP
```

То есть Ethernet переносит данные протоколов более высокого уровня.

## FCS

`FCS` (`Frame Check Sequence`) используется для проверки кадра на ошибки.

Отправитель вычисляет контрольное значение, а получатель проверяет его.

```text
Frame
  ↓
ошибка при передаче?
  ↓
FCS не совпадает
  ↓
кадр отбрасывается
```

Ethernet сам по себе обычно не выполняет повторную передачу такого кадра.

## MAC-адреса

Ethernet использует MAC-адреса для доставки кадров внутри локального сегмента сети.

Например:
```text
PC
MAC A
   ↓
Switch
   ↓
Server
MAC B
```

Кадр:
```text
Source MAC:      MAC A
Destination MAC: MAC B
```

Если получатель находится в другой IP-сети, устройство отправляет Ethernet-кадр не напрямую конечному серверу, а своему роутеру:
```text
Destination IP:
8.8.8.8

Destination MAC:
MAC default gateway
```

То есть:
```text
IP → конечный получатель
MAC → следующий узел в текущем сегменте
```

## Switch

Ethernet тесно связан с работой коммутаторов.

Switch запоминает:
```text
MAC → Port
```

Например:
```text
AA:AA:AA:AA:AA:AA → port 1
BB:BB:BB:BB:BB:BB → port 2
```

Если приходит кадр для:
```text
BB:BB:BB:BB:BB:BB
```

switch отправляет его на:
```text
port 2
```

## Broadcast

Ethernet поддерживает широковещательную передачу.

Специальный MAC:
```text
FF:FF:FF:FF:FF:FF
```

означает:
```text
Отправить кадр всем устройствам
в текущем broadcast domain
```

Например, broadcast используется [[ARP]].

## Ethernet и VLAN

[[VLAN]] позволяет логически разделить одну Ethernet-сеть на несколько отдельных сетей.

Для этого используется стандарт:
```text
802.1Q
```

В Ethernet-кадр добавляется информация:
```text
VLAN ID
```

Например:
```text
Frame
VLAN 10
```

Это позволяет одному физическому switch обслуживать несколько изолированных VLAN.

## Скорость

Ethernet существует в разных вариантах скорости.

Например:
```text
100 Mbit/s
1 Gbit/s
2.5 Gbit/s
10 Gbit/s
100 Gbit/s
```

Конкретная скорость зависит от оборудования и типа физического соединения.

## Кратко

```text
Ethernet
 │
 ├─ используется в локальных сетях
 ├─ передаёт кадры
 ├─ использует MAC-адреса
 ├─ работает со switch
 ├─ поддерживает broadcast
 ├─ может переносить IPv4, IPv6, ARP
 └─ поддерживает VLAN через 802.1Q
```

Главная идея:

```text
IP отвечает:
куда должен попасть пакет

Ethernet отвечает:
как передать кадр следующему устройству
в текущем сегменте сети
```
