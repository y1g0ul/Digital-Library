`User Datagram Protocol` - транспортный протокол для быстрой передачи данных **без установки соединения** и без гарантии доставки.

В отличие от TCP, перед отправкой данных не происходит handshake.

```text
Sender
  ↓
UDP Datagram
  ↓
Receiver
```

Отправитель просто отправляет датаграмму получателю.

UDP не гарантирует:
- доставку;
- правильный порядок;
- отсутствие дубликатов;
- повторную передачу потерянных данных.

Например:
```text
Datagram 1 → ✓
Datagram 2 → X потеряна
Datagram 3 → ✓
```

UDP не будет самостоятельно отправлять `Datagram 2` повторно.

Если приложению нужна надёжность, оно должно реализовать её самостоятельно.

## Заголовок UDP

UDP-заголовок очень маленький - всего **8 байт**.

Он содержит четыре поля:
1. **Source Port** - порт отправителя.
2. **Destination Port** - порт получателя.
3. **Length** - длина всей UDP-датаграммы вместе с заголовком и данными.
4. **Checksum** - контрольная сумма для обнаружения повреждения данных.

Схематично:
```text
UDP Datagram

┌──────────────────────┐
│ Source Port          │
├──────────────────────┤
│ Destination Port     │
├──────────────────────┤
│ Length               │
├──────────────────────┤
│ Checksum             │
├──────────────────────┤
│ Data                 │
└──────────────────────┘
```

## Почему UDP быстрее и проще

UDP не тратит время на:
- установку соединения;
- подтверждения;
- повторную передачу;
- контроль порядка;
- управление потоком.

Поэтому накладные расходы у него меньше.

```text
TCP:
установка соединения
подтверждения
контроль доставки
повторная передача
...

UDP:
отправил → всё
```

Но это не означает, что UDP всегда «быстрее по сети». Он просто имеет меньше встроенных механизмов.

## Где используется

UDP удобен там, где важнее скорость и небольшая задержка, чем гарантированная доставка каждого сообщения.

Например:
```text
DNS
DHCP
VoIP
онлайн-игры
видеозвонки
стриминг
```

В реальном времени иногда лучше потерять один пакет, чем ждать его повторной передачи.

Например, в голосовом звонке:
```text
потерялся небольшой кусок звука
        ↓
может быть почти незаметно
```

Если ждать повторную передачу:
```text
пауза
задержка
рывок звука
```

## UDP и датаграммы

TCP передаёт **поток байтов**, а UDP - отдельные сообщения, которые называются датаграммами.

```text
TCP:

байты → непрерывный поток


UDP:

Datagram 1
Datagram 2
Datagram 3
```

Границы датаграмм сохраняются.

То есть одна отправленная UDP-датаграмма остаётся отдельным сообщением на стороне получателя.

## Кратко

```text
UDP
 │
 ├─ нет соединения
 ├─ нет гарантии доставки
 ├─ нет повторной передачи
 ├─ нет контроля порядка
 ├─ маленький заголовок
 └─ низкие накладные расходы
```

Главная идея:
```text
UDP просто отправляет датаграммы.
Надёжность, если она нужна, должна обеспечиваться приложением.
```
