Протокол [[IPv6]], который используется для обнаружения соседних устройств и получения информации о сети. Он выполняет несколько задач, которые в [[IPv4]] распределены между [[ARP]], частью функций [[ICMP]] и механизмами автоконфигурации. Работает поверх `ICMPv6`.
- определения [[MAC]]-адреса соседа по его IPv6-адресу;
- обнаружения маршрутизаторов;
- получения сетевых параметров;
- проверки доступности соседей;
- обнаружения дублирующихся IPv6-адресов;
- автоматической настройки IPv6-адресов через `SLAAC`.

## Определение MAC-адреса

В IPv4 для этого используется:
```text
ARP
IP → MAC
```

В IPv6 эту задачу выполняет NDP. Допустим, устройство хочет узнать MAC получателя:
```text
2001:db8::20
```

Оно отправляет сообщение:
```text
Neighbor Solicitation
```

В ответ нужное устройство отправляет:
```text
Neighbor Advertisement
```

Смысл примерно такой:
```text
NS:
Кто использует IPv6 2001:db8::20?

NA:
2001:db8::20 находится по MAC
AA:BB:CC:DD:EE:FF
```

Полученное соответствие сохраняется в таблице соседей:
```text
IPv6 → MAC
```

Посмотреть её в Linux:
```bash
ip -6 neigh
```

или:
```bash
ip neigh
```

## В отличие от ARP

ARP использует broadcast:
```text
FF:FF:FF:FF:FF:FF
```

В IPv6 broadcast вообще отсутствует. Вместо него NDP использует `multicast`. Например, Neighbor Solicitation отправляется на специальный `solicited-node multicast` адрес, соответствующий искомому IPv6-адресу. Это позволяет не заставлять все устройства сети обрабатывать каждый запрос.

## Router Solicitation и Router Advertisement

NDP также позволяет находить IPv6-маршрутизаторы.

Хост может отправить:
```text
Router Solicitation (RS)
```

Примерный смысл:
```text
Есть ли здесь IPv6-роутер?
```

Роутер отвечает:
```text
Router Advertisement (RA)
```

В RA может содержаться:
- IPv6-префикс сети;
- адрес или информация о default gateway;
- параметры автоконфигурации;
- MTU;
- информация, связанная с DNS;
- время жизни маршрута.

Благодаря этому устройство может автоматически настроить IPv6 без ручного указания адреса.

## SLAAC

`SLAAC` (`Stateless Address Autoconfiguration`) позволяет устройству самостоятельно создать IPv6-адрес на основе информации из Router Advertisement.

Упрощённо:
```text
Router Advertisement
        ↓
Префикс сети:
2001:db8:1234:1::/64
        ↓
Хост создаёт себе адрес:
2001:db8:1234:1:xxxx:xxxx:xxxx:xxxx
```

Поэтому в IPv6 для получения адреса DHCPv6 нужен не всегда.

## Duplicate Address Detection

Перед использованием нового IPv6-адреса устройство проверяет, не используется ли он уже кем-либо.

Этот механизм называется:
```text
DAD — Duplicate Address Detection
```

Для проверки также используются сообщения Neighbor Solicitation. Если никто не отвечает, адрес считается свободным.

## Neighbor Unreachability Detection

NDP может определять, доступен ли сосед.

Этот механизм называется:
```text
NUD — Neighbor Unreachability Detection
```

ОС хранит состояние соседей, например:
```text
REACHABLE
STALE
DELAY
PROBE
FAILED
```

Их можно увидеть:
```bash
ip -6 neigh
```

## Основные сообщения NDP

|Сообщение|Назначение|
|---|---|
|`Neighbor Solicitation (NS)`|поиск соседа / его MAC|
|`Neighbor Advertisement (NA)`|ответ соседа|
|`Router Solicitation (RS)`|поиск роутера|
|`Router Advertisement (RA)`|информация от роутера|
|`Redirect`|сообщение о более подходящем маршруте|

Все они являются сообщениями `ICMPv6`.

## Кратко

```text
IPv4:
ARP → IP → MAC

IPv6:
NDP → IPv6 → MAC
     → поиск роутеров
     → автоконфигурация
     → проверка соседей
     → проверка дубликатов адресов
```

То есть NDP - это не просто «ARP для IPv6», а более широкий механизм обнаружения и настройки устройств в IPv6-сети.
