Dynamic Host Configuration Protocol - протокол, который автоматически выдаёт устройствам сетевые настройки.

Без DHCP адреса пришлось бы настраивать вручную.

Обычно DHCP выдаёт:
- [[networks/IP|IP]]-адрес;
- [[Маска подсети|маску подсети]];
- default gateway;
- [[DNS]]-серверы;
- время аренды адреса.

## Пример

Устройство подключается к сети:
```text
Ноутбук
   ↓
DHCP Server
   ↓
IP:      192.168.1.20
Mask:    255.255.255.0
Gateway: 192.168.1.1
DNS:     192.168.1.1
```

После этого устройство может нормально работать в сети.

## Как работает DHCP

Классический процесс состоит из четырёх шагов:
```text
DORA
```

### 1. DHCP Discover

Клиент только подключился к сети и ещё не знает:
- свой IP;
- адрес DHCP-сервера.

Поэтому он отправляет широковещательный запрос:
```text
Есть ли здесь DHCP-сервер?
```

Это сообщение:
```text
DHCP Discover
```

## 2. DHCP Offer

DHCP-сервер отвечает:
```text
Могу выдать тебе:

IP: 192.168.1.20
Mask: /24
Gateway: 192.168.1.1
DNS: 192.168.1.1
```

Это сообщение:
```text
DHCP Offer
```

## 3. DHCP Request

Клиент сообщает:
```text
Хочу использовать предложенный адрес.
```

Отправляется:
```text
DHCP Request
```

## 4. DHCP ACK

Сервер подтверждает выдачу адреса:
```text
DHCP ACK
```

После этого клиент может использовать полученные настройки.

Схематично:
```text
Client                       DHCP Server

Discover -------------------->

             <---------------- Offer

Request --------------------->

             <---------------- ACK
```

## Почему используется broadcast

В начале клиент ещё не знает:
```text
свой IP
IP DHCP-сервера
```

Поэтому первый запрос отправляется в локальную сеть широковещательно.

В IPv4 при этом можно увидеть:
```text
Source IP:
0.0.0.0

Destination IP:
255.255.255.255
```

То есть:
```text
Я ещё не знаю свой адрес
        ↓
Отправляю запрос всем в локальной сети
```

## Порты

DHCP работает через [[UDP]].

Используются порты:
```text
UDP 67 → DHCP Server
UDP 68 → DHCP Client
```

## Lease

IP-адрес обычно выдаётся не навсегда, а на определённое время.

Это называется:
```text
Lease
```

Например:
```text
192.168.1.20
Lease: 24 часа
```

До окончания аренды клиент пытается её продлить.

Если продление успешно:
```text
клиент продолжает использовать тот же IP
```

Если нет:
```text
адрес освобождается
```

и сервер может выдать его другому устройству.

## DHCP Pool

DHCP-сервер обычно имеет диапазон адресов, которые может выдавать клиентам.

Например:
```text
192.168.1.100
        -
192.168.1.200
```

Это называется:
```text
DHCP Pool
```

Пример:
```text
Router:
192.168.1.1

DHCP Pool:
192.168.1.100-192.168.1.200
```

## DHCP Reservation

Иногда нужно, чтобы конкретное устройство всегда получало один и тот же IP.

Для этого можно создать:
```text
DHCP Reservation
```

Например:
```text
MAC:
AA:BB:CC:DD:EE:FF

        ↓

всегда выдавать:

192.168.1.50
```

Это удобно для:
- серверов;
- принтеров;
- камер;
- NAS;
- других постоянных устройств.

## DHCP Relay

DHCP Discover обычно не проходит через маршрутизаторы.

Но DHCP-сервер необязательно должен находиться в каждой подсети.

Можно использовать:
```text
DHCP Relay
```

Например:
```text
Client
192.168.10.0/24
      ↓
Router
DHCP Relay
      ↓
DHCP Server
192.168.100.10
```

Роутер принимает DHCP-запрос и передаёт его DHCP-серверу в другой сети.

## DHCP и IPv6

В IPv6 существует:
```text
DHCPv6
```

Но IPv6-устройство может получить адрес и без DHCP через:

```text
NDP
+
Router Advertisement
+
SLAAC
```

Поэтому DHCPv6 используется не всегда.

## Кратко

```text
DHCP
 │
 ├─ автоматически выдаёт IP
 ├─ выдаёт маску
 ├─ выдаёт gateway
 ├─ выдаёт DNS
 ├─ использует UDP 67/68
 └─ адрес обычно выдаётся временно
```

Главный процесс:

```text
Discover
   ↓
Offer
   ↓
Request
   ↓
ACK
```

`DHCP` избавляет администратора от необходимости вручную настраивать сетевые параметры на каждом устройстве.
