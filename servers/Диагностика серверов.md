Главный принцип диагностики - идти от простого к сложному и последовательно исключать возможные причины.

## Сервер недоступен

Упрощённый алгоритм:
```
Сервер недоступен
       ↓
Проверить monitoring
       ↓
Есть ли питание?
       ↓
Есть ли сеть?
       ↓
Работает ли BMC/IPMI?
       ↓
Загружается ли сервер?
       ↓
Загружена ли ОС?
       ↓
Работает ли нужный сервис?
```

## 1. Питание

Проверяем:
- включён ли сервер;
- состояние [[Питание, UPS и PDU|PDU]];
- состояние розетки;
- наличие напряжения;
- потребляемый ток;
- состояние блоков питания.

Если сервер имеет два PSU, проверяем обе линии.

## 2. Сеть

Проверяем:
- физическое подключение;
- link на сетевом интерфейсе;
- [[networks/IP|IP]]-адрес;
- маршрутизацию;
- доступность шлюза;
- [[VLAN]];
- доступность устройства по [[ping]].

Инструменты:
- [[ping]]
- [[linux/ip|ip]] addr
- ip route
- [[traceroute]]


## 3. BMC / IPMI

Если ОС недоступна, используем [[OOB|Out-of-Band Management]].

Через BMC можно проверить:
- состояние питания;
- температуры;
- вентиляторы;
- состояние CPU и RAM;
- аппаратные события;
- KVM-консоль.

## 4. POST

**POST - Power-On Self Test.**

Выполняется при включении сервера.

Проверяет основные аппаратные компоненты.

Ошибки могут отображаться:
- POST-кодами;
- звуковыми сигналами;
- сообщениями в KVM;
- журналами BMC.

## 5. RAM

При проблемах с памятью можно:
- посмотреть аппаратные логи;
- проверить ошибки ECC;
- переставить модуль;
- протестировать модули по одному;
- проверить слоты.

Физические действия выполняются только при отключённом питании и с соблюдением процедур обслуживания.

## 6. Диски

Проверяем:
- видит ли контроллер диск;
- состояние RAID;
- SMART;
- аппаратные ошибки;
- состояние backplane;
- состояние HBA/RAID-контроллера.

## 7. Загрузка

Если сервер включён, но ОС не запускается:
- открыть KVM;
- посмотреть ошибки BIOS/UEFI;
- проверить boot order;
- проверить наличие загрузочного диска;
- при необходимости использовать PXE или Live-систему.

## 8. Сервис

Если сервер и ОС работают, но приложение недоступно:
- [[systemctl]] status
- [[journalctl]]
- [[ss]]
- [[curl]]
- [[nc]]


Проверяем:
- запущен ли сервис;
- слушает ли нужный порт;
- есть ли ошибки в логах;
- работает ли firewall;
- доступен ли сервис по сети.

Главная идея:
```
Питание
   ↓
Железо
   ↓
Сеть
   ↓
ОС
   ↓
Сервис
```

Диагностика должна идти последовательно, а не случайным набором действий.
