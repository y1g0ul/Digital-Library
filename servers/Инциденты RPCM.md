Главный принцип диагностики - сначала определить, на каком уровне находится проблема:
```
Питание
   ↓
RPCM
   ↓
Сеть
   ↓
Конфигурация
   ↓
Подключённое оборудование
```

## 1. RPCM полностью недоступен

Симптом:
- не отвечает `ping`;
- не открывается Web UI;
- недоступен SSH;
- SNMP не отвечает.

Проверяем:
1. Есть ли питание у самого RPCM.
2. Есть ли link на сетевом интерфейсе.
3. Правильный ли IP-адрес.
4. Доступен ли шлюз.
5. Нет ли проблем с VLAN или маршрутизацией.
6. Доступен ли RPCM из другой точки сети.
7. Если сеть исправна — проверяем состояние самого устройства.


Упрощённо:
```
RPCM недоступен
      ↓
Есть питание?
      ↓
Есть link?
      ↓
IP / VLAN / route
      ↓
ping
      ↓
Web / SSH / SNMP
```

## 2. Ping работает, но Web UI не открывается

Это означает, что устройство доступно на сетевом уровне, но проблема может быть в конкретном сервисе.

Проверяем:
- правильный ли порт;
- HTTP или HTTPS используется;
- доступен ли TCP-порт;
- работает ли SSH;
- работает ли SNMP;
- нет ли ограничений firewall;
- нет ли ошибки веб-сервиса.

Инструменты:
```
ping <ip>
nc -vz <ip> 80
nc -vz <ip> 443
curl -vk https://<ip>
```

Главная идея:
> `ping` проверяет доступность устройства, но не гарантирует работу конкретного сервиса.

## 3. SNMP не работает

Симптом:
- устройство доступно;
- Web UI работает;
- SNMP-мониторинг перестал получать данные.

Проверяем:
- включён ли [[SNMP]];
- правильная ли версия SNMP;
- правильный ли community string или учётные данные SNMPv3;
- доступен ли [[UDP]]-порт;
- правильный ли IP monitoring-сервера;
- разрешён ли доступ с его адреса;
- корректны ли OID/MIB.

Можно проверить вручную:
```
snmpget
snmpwalk
```

## 4. Не работает один outlet

Симптом:
- RPCM работает;
- остальные выходы работают;
- одно подключённое устройство выключено.

Проверяем:
- включён ли outlet;
- не сработала ли защита;
- есть ли ток;
- есть ли напряжение;
- исправен ли подключённый кабель;
- исправен ли PSU оборудования;
- не установлен ли запрет на включение;
- нет ли события в журнале RPCM.

Если ток равен нулю, возможны варианты:
```
Outlet OFF
или
кабель отключён
или
PSU неисправен
или
оборудование выключено
```

## 5. Сработала защита по току

Симптом:
- outlet автоматически отключился;
- в журнале есть событие overcurrent.

Проверяем:
- какой ток потребляло устройство;
- установленный лимит;
- не было ли резкого скачка нагрузки;
- исправно ли подключённое оборудование;
- не произошло ли короткое замыкание.

Не следует просто включать outlet снова, не выяснив причину.

## 6. Короткое замыкание

Симптом:
- конкретный выход отключился;
- RPCM сообщил о short circuit или защите.

Порядок:
```
Отключить проблемный выход
        ↓
Не включать повторно вслепую
        ↓
Проверить оборудование / кабель
        ↓
При необходимости эскалировать
```

Главная задача защиты — не допустить падения остальных устройств.

## 7. ATS переключился на резервный ввод

Симптом:
- RPCM сообщил о смене источника питания.

Проверяем:
- состояние Source A;
- состояние Source B;
- напряжение на обоих вводах;
- почему основной источник вышел из допустимых параметров;
- вернулось ли питание;
- произошло ли обратное переключение.

Важно понять не только факт переключения, но и причину.

## 8. Watchdog постоянно перезагружает сервер

Симптом:
- сервер регулярно делает power cycle;
- RPCM считает его недоступным.

Проверяем:
- по какому условию настроен watchdog;
- правильный ли [[networks/IP|IP]];
- доступен ли [[ICMP]];
- правильный ли [[TCP]]-порт;
- не блокирует ли firewall проверки;
- корректный ли таймаут;
- не слишком ли мало попыток;
- действительно ли сервер зависает.

Возможная проблема:
```
Server работает
      ↓
Firewall блокирует ping
      ↓
Watchdog считает Server мёртвым
      ↓
Power cycle
```

То есть проблема может быть не в сервере, а в неправильно настроенном watchdog.

## 9. Сервер не отвечает, но потребляет ток

Симптом:
- ток на outlet есть;
- сервер по сети недоступен.

Это говорит о том, что питание присутствует, но сервер может:
- зависнуть;
- иметь проблему с ОС;
- иметь проблему с сетью;
- иметь неисправный NIC;
- находиться в процессе загрузки.

Дальше проверяем:
```
Network
  ↓
BMC/IPMI
  ↓
KVM
  ↓
OS
```

## 10. Сервер не отвечает и ток почти отсутствует

Возможные причины:
- сервер выключен;
- PSU не работает;
- outlet выключен;
- кабель отключён;
- сработала защита.

Здесь сначала проверяем питание, а не Linux.

## 11. Клиент не может включить outlet

Проверяем:
- права пользователя;
- текущее состояние outlet;
- блокировки;
- защитные события;
- состояние входного питания;
- настройки RPCM;
- команды через Web/SSH/API.

Если команда поступает, но outlet не включается — проблема может быть уже аппаратной.

## 12. Неверные показания тока или мощности

Проверяем:
- действительно ли нагрузка изменилась;
- показания других каналов;
- настройки измерения;
- журнал событий;
- нет ли проблемы с датчиком;
- соответствует ли измерение ожидаемому потреблению оборудования.

Если значения физически невозможны или сильно отличаются от реальности — эскалация на более высокий уровень.

## Общая схема L2

```
Получили alert / ticket
        ↓
Уточнили симптом
        ↓
Проверили monitoring
        ↓
Определили уровень проблемы
        ↓
Питание / RPCM / сеть / конфиг / сервер
        ↓
Собрали факты и логи
        ↓
Исправили
        или
Эскалировали на L3
```

Хороший ответ на собеседовании строится не вокруг случайных команд, а вокруг последовательного исключения причин.
