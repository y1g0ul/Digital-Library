Управляемое устройство распределения электропитания для серверного и телекоммуникационного оборудования.

Главная идея:
```
Источник питания
       ↓
     RPCM
       ↓
 ┌─────┼─────┐
Server Switch Router
```

В отличие от обычного PDU, RPCM умеет не только раздавать питание, но и:
- контролировать отдельные выходы;
- измерять параметры электропитания;
- удалённо включать и выключать оборудование;
- защищать выходы;
- автоматически переключаться на резервный источник;
- перезапускать зависшее оборудование.

## Управление выходами

Каждый выход может управляться отдельно.

Можно:
- включить;
- выключить;
- выполнить power cycle;
- посмотреть состояние;
- посмотреть ток и мощность.

Пример:
```
Outlet 1 → Server
Outlet 2 → Switch
Outlet 3 → Router
```

Если проблема только с Server, можно воздействовать на `Outlet 1`, не отключая остальные устройства.

## Мониторинг питания

RPCM может контролировать:
- напряжение;
- ток;
- мощность;
- энергопотребление;
- состояние отдельных выходов.

Эти данные могут использоваться для мониторинга и диагностики.

## Защита

RPCM может защищать оборудование от:
- перегрузки по току;
- короткого замыкания;
- проблем с входным питанием.

Одна из важных идей - локализовать проблему на конкретном выходе, чтобы неисправное устройство не отключило остальные.

## ATS

RPCM может работать с двумя источниками питания.

```
Source A ─┐
          ├── RPCM ─── Equipment
Source B ─┘
```

Если основной источник питания пропадает или выходит за допустимые параметры, устройство может переключить нагрузку на резервный.

## Watchdog

RPCM может контролировать доступность подключённого оборудования.

Проверка может выполняться, например, по:
- [[ICMP]]/[[ping]];
- [[TCP]]-порту;
- потребляемому току.

Если устройство перестаёт отвечать, RPCM может автоматически выполнить power cycle.

Пример:
```
Server не отвечает на ping
        ↓
Watchdog фиксирует несколько ошибок
        ↓
Outlet OFF
        ↓
Пауза
        ↓
Outlet ON
        ↓
Server перезагружается
```

## Интерфейсы управления

RPCM может управляться через:
- Web UI;
- [[networks/SSH|SSH]];
- [[SNMP]];
- REST API.

Дополнительно могут использоваться:
- SNMP Trap;
- SMTP;
- RADIUS.

## SNMP

Через SNMP система мониторинга может получать:
- состояние выходов;
- ток;
- напряжение;
- мощность;
- аварийные события.

Устройство также может самостоятельно отправлять SNMP Trap при возникновении события.

## REST API

REST API позволяет программно получать состояние устройства и управлять им.

Например, систему можно интегрировать с:
- мониторингом;
- внутренними сервисами;
- скриптами автоматизации.

## Типовые задачи RPCM

```
Мониторинг питания
        +
Удалённое управление
        +
Резервирование
        +
Защита
        +
Автоматическое восстановление
```

RPCM находится на стыке:
- электротехники;
- сетей;
- серверной инфраструктуры;
- мониторинга;
- автоматизации.
