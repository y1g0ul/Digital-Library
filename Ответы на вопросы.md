- Чем git pull отличается от git fetch?

	Ответ: git fetch только синхронизирует локальное представление удаленных репозиториев с тем, что является актуальным на текущий момент времени. Команда всего лишь скачивает все необходимые данные, но дальше потребуется вручную слить эти данные с вашими. git pull не только вытягивает изменения с удаленного репозитория но и обьединяет с нашим.

- Чем в linux отличается soft link от hard link? Какое поведение будет при удалении файла оригинала? Можно ли создать hardlink на директорию?

	Ответ: Символическая ссылка это просто «ярлык». Если удалить `myfile`, ссылка `myfile3` станет «битой» (не будет работать). Права доступа для `myfile3` не имеют значения — они наследуются от `myfile`. Может создаваться на каталоги в разных дисках. Символическая ссылка содержит в себе **относительный** пута до файла на которые она указывает, а не **абсолютный**. Символическая ссылка до 60 байт использует **быстрый (fast) режим**, при котором путь целевого файла хранится прямо в структурах inode файловой системы (например, ext4), без выделения отдельного дискового блока. Ссылки длиннее 60 байт работают в **обычном (slow) режиме** и требуют выделения полноценного дискового блока для хранения пути. Если за 40 шагов до реального файла не добрались, тогда ядро вернет ошибку. Жёсткие ссылки это  имена для одних и тех же данных. Если изменить содержимое одного файла, оно изменится и в другом. Удаление одного файла не удалит данные, пока есть другая ссылка. Создаётся только на файлы и в пределах одного диска. Нельзя создавать на файлы в разных дисках ведь у каждого диска уникальные inode. Нельзя создавать на каталоги.
